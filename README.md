# CNN-BiLSTM for Real-time Neural Spike Sorting

**Paper:** "Real-time Neural Spike Sorting and Morphology Estimation Using Hybrid CNN-BiLSTM Architectures for Brain-Computer Interface Applications"
**Author:** Dr. Firas Almukhtar
**License:** Apache-2.0 (see [LICENSE](LICENSE))

This repository contains the implementation of the CNN-BiLSTM model described in the paper: preprocessing, training, evaluation, and the Random Forest / XGBoost baselines used for Tables V and VI of the paper.

> **Scope note.** The scripts for Table VII (Kilosort/YASS comparison), Table VIII (low-label regime), Table IX (architecture comparison), the ablation, drift and noise-robustness experiments, the fuzzy-thresholding and Pareto-screening analyses, and the permutation/effect-size tests are **not included in this repository**, and no pre-trained weights are published yet. The sections below document only what is currently available.

## Architecture overview

The CNN-BiLSTM model (Algorithm 1, Section III.C) integrates:

- **CNN stage:** 3 Conv1D layers (64 → 128 → 256 filters, kernel = 3) + ELU + AvgPool
- **BiLSTM stage:** 2 bidirectional LSTM layers (128 units each)
- **Dual output:** classification (Softmax) + morphology prediction (Linear, 47 PCA coefficients)
- **Total parameters:** 952,507 for K = 12 output classes (Table III)

## Quick start

### 1. Preprocess data

```bash
python preprocess.py \
  --input data/raw/quiroga_dataset.npy \
  --output-dir data/quiroga \
  --dataset-name quiroga \
  --sampling-rate 24000 \
  --pca-variance 0.952 \
  --k-threshold 4.5
```

This step implements:

- Bandpass filtering (300–3000 Hz Butterworth), Section III.A.2
- Adaptive thresholding T(t) = μ(t) + 4.5·σ(t), Equation 1, Section III.B.1
- 200-sample waveform extraction (100 before, 100 after crossing), Section III.B.2
- PCA to 47 components (95.2% variance), computed only on the training set, Section III.B.2
- Temporal splits: 70% train / 10% validation / 20% test (not random), Section III.A.1

### 2. Train the CNN-BiLSTM model

```bash
# Quiroga simulated benchmark: 3 units per recording (batch size 32)
python train.py \
  --dataset quiroga \
  --num-classes 3 \
  --batch-size 32 \
  --epochs 100 \
  --lr 0.001 \
  --lambda-weight 0.5 \
  --model-dir models/quiroga \
  --data-dir data/quiroga
```

Training configuration (Table IV):

- Optimizer: Adam (β₁ = 0.9, β₂ = 0.999, ε = 1e-7)
- Initial learning rate: 0.001
- LR reduction: divide by 2 after 10 epochs with no improvement
- Early stopping: patience = 15, min_delta = 0.001
- Loss: combined classification + prediction (Equation 6, λ = 0.5)
- Teacher forcing: full during training, disabled at inference (Section III.D.1)
- Random seed: 42 (10-run averaging for stability)

For a second dataset, use `--dataset <name> --num-classes <K>`; `--batch-size` defaults to 32 for `quiroga` and 64 otherwise.

### 3. Evaluate the model

```bash
python evaluate.py \
  --model-weights models/quiroga/best_model_quiroga.h5 \
  --test-data data/quiroga/quiroga_preprocessed.npz \
  --num-classes 3 \
  --output-dir results/quiroga
```

This computes:

- Accuracy, precision, recall (Section III.D.4)
- BCa bootstrap confidence intervals (B = 10,000, stratified by neuron class), Section III.D.5
- Bayesian validation (Beta(1,1) prior, MCMC 4 chains × 4000 iterations), Section III.D.5
- Calibration (ECE, 10 bins; Brier score), Section III.D.4
- Latency (single-spike and batch), Section III.E.3

Results are written to `results/quiroga/evaluation_results.json`.

### 4. Train and evaluate baselines

```bash
# Random Forest and XGBoost
python baselines.py \
  --data data/quiroga/quiroga_preprocessed.npz \
  --output-dir results/quiroga \
  --model all

# Or individually
python baselines.py --model rf  --data data/quiroga/quiroga_preprocessed.npz
python baselines.py --model xgb --data data/quiroga/quiroga_preprocessed.npz
```

Baseline configurations (Section III.F):

- Random Forest: 500 trees, max_depth = 20
- XGBoost: learning_rate = 0.1, max_depth = 6, early stopping

Both receive the same 47-component PCA features.

## Reproducing paper results

### Table V: CNN-BiLSTM performance metrics

Replace `<dataset>` and `<K>` with the dataset name and its number of classes (for the simulated Quiroga benchmark, `quiroga` and `3`). Quiroga is a simulated benchmark, not a recording from animals.

```bash
python train.py --dataset <dataset> --num-classes <K> --batch-size 32 \
  --model-dir models/<dataset> --data-dir data/<dataset>
python evaluate.py --model-weights models/<dataset>/best_model_<dataset>.h5 \
  --test-data data/<dataset>/<dataset>_preprocessed.npz --num-classes <K> \
  --output-dir results/<dataset>
```

| Metric | Reported value |
|--------|----------------|
| Accuracy | 0.964 [0.962, 0.967] (BCa 95% CI) |
| Precision | 0.948 [0.945, 0.952] |
| Recall | 0.951 [0.947, 0.954] |
| Latency (amortized) | ~45.2 ms (NVIDIA RTX 3090) |
| Latency (single spike) | ~52.1 ms (NVIDIA RTX 3090) |

## Model architecture details

### Algorithm 1: CNN-BiLSTM inference pipeline

Implemented in `model.py` (`CNNBiLSTMSpikeSorter`):

```text
# Stage 1: Spatial feature extraction (CNN layers 1-9)
h1 = Conv1D(x, kernel=3, filters=64)        # Layer 1
h2 = ELU(h1, alpha=1.0)                     # Layer 2
h3 = AvgPool(h2, pool=2)                    # Layer 3
h4 = Conv1D(h3, kernel=3, filters=128)      # Layer 4
h5 = ELU(h4, alpha=1.0)                     # Layer 5
h6 = AvgPool(h5, pool=2)                    # Layer 6
h7 = Conv1D(h6, kernel=3, filters=256)      # Layer 7
h8 = ELU(h7, alpha=1.0)                     # Layer 8
h9 = GlobalAvgPool(h8)  -> 256-dim vector   # Layer 9

# Stage 2: Temporal modeling (BiLSTM layers 10-13)
h10 = Reshape(h9, to=[1 x 256])             # Layer 10
[h_fwd, h_bwd] = BiLSTM(h10, units=128 x 2) # Layer 11
h12 = Dropout([h_fwd, h_bwd], rate=0.3)     # Layer 12
[h_fwd, h_bwd]_2 = BiLSTM(h12, units=128 x 2)  # Layer 13
h13 = Dropout([h_fwd, h_bwd]_2, rate=0.2)   # Layer 14-prep

# Stage 3: Dual-output generation (layers 14-16)
z = Dense(h13, units=128, ReLU)             # Layer 14
z_drop = Dropout(z, rate=0.2)               # Layer 15

# Output 16a: classification
y_hat = Softmax(Dense(z_drop, units=K))     # K neuron classes

# Output 16b: morphology prediction
y_pred = Linear(Dense(z_drop, units=47))    # 47 PCA coefficients
```

### Key design choices

- Sequence length: 16 consecutive spikes (Section III.C.2)
- Zero-padding: left for the first 15 spikes, right for the final spikes
- Prediction scope: single-step forecast of the next detected spike's morphology
- Prediction invalidation: if ISI > 500 ms (Section III.C.3)
- Value clipping: [-5, +5] standard deviations during training

## Known limitations

From Section VI.B of the paper:

1. **Computational cost:** high FLOP count; GPU acceleration is required.
2. **Predictive limitation:** predicts morphology (PCA coefficients) only, not ISI or spike timing.
3. **Cross-dataset generalization:** 12.2% drop (motor cortex → hippocampus), 14.7% drop (rodent → primate).
4. **Supervision dependency:** 96.4% accuracy requires full labels; 10% labels yield 88.9%.
5. **Single-electrode processing:** 12% over-splitting for multi-electrode recordings.
6. **Reproducibility:** the proprietary MEA dataset cannot be redistributed.
